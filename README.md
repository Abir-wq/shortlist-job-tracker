# Shortlist

**A little clarity for your next career move.**

Shortlist is a full-stack job-application tracker with a React frontend, a separate Express API, and PostgreSQL storage. It combines an application pipeline with follow-up planning and a personal interview notebook.

The code uses JavaScript, ordinary CSS, React state and plain SQL. There is no ORM, Redux, AI API, payment system, or external job scraper. AI assistance was used to build this starter; study and customise it before presenting it as your portfolio work.

## Start here

1. Install **Node.js 22.12 or newer** (Node 24.22.1 was used for this package).
2. Extract this ZIP into a normal folder and open that folder in VS Code.
3. Open a terminal in the folder containing `package.json`.
4. Run:

```bash
npm ci
npm run setup
```

5. Create a **new PostgreSQL database**. You can use Neon or an existing local PostgreSQL installation. Do not reuse a database containing another project's tables.
6. Open the newly created `.env` file. Replace only `DATABASE_URL` with your database connection string. Keep the random `SESSION_SECRET` generated by setup.
7. Run:

```bash
npm run db:migrate
npm run dev
```

8. Open **http://localhost:5173**. Click **Create an account**.
9. Add your first application, or click **Explore with sample data** on the empty overview.

You do not need Google/GitHub OAuth keys, a mail service, or any paid API. Do not put the database URL in React code or a `VITE_` variable.

### What the two development servers do

- React / Vite: `http://localhost:5173`
- Express API: `http://localhost:3001/api`
- Vite forwards `/api` requests to Express. Keep `PORT=3001` for the default development proxy.
- Both servers start with `npm run dev`; Ctrl+C stops both.
- Open the Vite URL during development. The API serves the built frontend only after `npm run build`.

## Features

- Email/password registration, sign-in and sign-out.
- Password hashing, PostgreSQL-backed sessions and account-specific records.
- Create, view, edit and delete applications.
- Five stages: Saved, Applied, Interview, Offer and Closed.
- Search by company, role or location; filter by stage; sort by date or company.
- List and card views with clear empty, loading and error states.
- A next-action field, follow-up dates and overdue labels.
- Interview scheduling displayed in the viewer's device time zone.
- Per-application preparation checklist, editable questions and saved answers.
- CSV export of the currently filtered application list.
- Six clearly labelled fictional sample applications; remove samples without deleting your own records.
- Responsive sidebar/mobile navigation, labelled forms, keyboard focus indicators and reduced-motion support.

## A few deliberate details

The overview answers “What should I do next?” rather than only counting applications. Closed applications stay in your history but no longer appear in follow-ups. The interview room measures preparation by completed checklist items, not an invented readiness score. All sample companies are fictional and no real job listings are scraped.

## Deploy

Read **[docs/DEPLOY.md](docs/DEPLOY.md)** for the exact Render + Neon steps.

React and Express have separate source folders and development servers. For the simplest reliable deployment, Express serves the compiled React files and `/api` at one public address. You still have a separate Express backend; serving the frontend from it avoids cross-domain cookies and CORS configuration.

**This ZIP is deployment-ready source, not an already deployed website.** You must create the database and hosting service and supply your own configuration. Never reuse credentials previously posted in chat or committed to another repository.

## Commands

| Command | Purpose |
| --- | --- |
| `npm ci` | Install the versions in package-lock.json |
| `npm run setup` | Create .env with a random local session secret |
| `npm run db:migrate` | Create tables and indexes, preserving existing records |
| `npm run dev` | Run React and Express during development |
| `npm run build` | Build React into client/dist |
| `npm start` | Run Express; serves built React at the same address |
| `npm test` | Run API tests against an isolated embedded PostgreSQL database |

For tests on a fresh checkout, run `npm run build` before `npm test`; one test checks the actual built page fallback. Tests do not need your DATABASE_URL and never connect to Neon.

## Scope and practical limits

- No password reset or email verification in this version. Use a password you can remember; do not use this demo as your only record of important applications.
- Follow-up reminders appear inside the app. There are no emails, push messages or background notifications.
- Save edits before navigating to another section. A reload/close warning protects unsaved form changes; navigation through the sidebar does not automatically save them.
- The app stores notes and links, not uploaded resumes or attachments.
- Saving a record from two tabs uses the most recent save; there is no live collaboration or version history.
- API rate limits are in memory, suitable for the documented single-instance deployment. A multi-instance service should use a shared rate-limit store.
- The simple idempotent schema script is enough for this initial release. Use versioned migrations before changing a deployed database's columns.
